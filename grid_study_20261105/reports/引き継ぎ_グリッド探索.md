# 引き継ぎメモ: 決算モメンタム パラメータグリッド探索

作成日: 2026-11-02

## 1. 目的
好決算翌日の買い(決算モメンタム)について、スコア閾値・保有日数・検証年数の最良の組合せを探す。
従来は `.env` の BACKTEST_YEARS / SCORE_THRESHOLD / HOLD_DAYS を手でずらして `ernings_momentum_lab_multi.py` を実行し、
結果を ImpTrace.xlsx(`Desktop\山口義個人\My\StockLab\アイデア\`)に貼っていた。これを自動化する。

## 2. 重要な発見: 先読みバイアス
別チャットの検証レポート(`好決算翌日寄付き買い バックテスト検証レポート.md`)の指摘を、コードで確認済み。

- `ernings_momentum_lab_multi.py` は、決算翌営業日の**終値・出来高**でLLMがスコアを付け、**同じ日の始値**で買っている(232-269行目)。
- 寄付きの時点では当日の終値は分からないため、実運用では再現できない。過去の勝率68〜71%・平均+3〜4%は戦略の有効性の根拠にならない。
- その他の懸念(生存者バイアス、強気相場のみ、比較対象なし、重複行、LLMモデルが実行ごとに違う、運用ルール未適用)は上記レポートを参照。

## 3. 作成・改修したもの
`grid_backtest.py`(新規。未コミット)

- LLM評価は(モデル・銘柄・決算日)ごとに1回だけ実行し、`llm_score_cache.json` に保存。再実行するとキャッシュ済みの分を飛ばして続きから動く。エラーになった評価はキャッシュしない。
- 閾値・保有日数・検証年数の組合せは、キャッシュ済みスコアからオフラインで再計算する。
- LLM関数と設定は `ernings_momentum_lab_multi.py` から import して再利用している。
- グリッドと設定は冒頭の定数: THRESHOLDS=[0,70,75,80,85,90]、HOLD_DAYS_LIST=[3,4,5,7,10]、YEARS_LIST=[3,5]、MIN_TRADES=20、ENTRY_LAG=1。

### 先読み排除の改修(反応確認型)
- 決算翌営業日の大引けでスコアを付け、**その翌営業日の始値**で買う(ENTRY_LAG=1)。保有日数は買った日を1日目として数える。
- 閾値 0 を「全決算を買う場合」の比較対象として出力する。
- 日経平均(^N225)の同期間リターンとの差(`avg_excess_pct`)を計算し、ランキングは超過リターン順にする。
- 同一銘柄・同一エントリー日の重複を除去する。
- 買値と反応日終値の差を `gap_pct` として明細に記録する(ギャップ別の集計は未実装)。

### 出力ファイル
- `grid_result.csv`: 全組合せの勝率・平均損益・超過リターン・中央値・最大損失・最大含み損
- `grid_events.csv`: イベント明細
- `llm_score_cache.json`: LLMスコアのキャッシュ(バックアップ: `llm_score_cache.bak.json`)

## 5. 別端末での再開手順
1. リポジトリを取得し、次を**手動でコピー**する(コミット対象外のため)。
   - `grid_backtest.py`
   - `llm_score_cache.json`(続きから再開するために必要)
   - `.env`(APIキーを含む。メモやチャットに貼らず、安全な手段で移す)
   - `ticker_list.txt`(差し替え済みの58銘柄のリスト。未コミットの変更あり)
2. 依存パッケージ: `openai`、`python-dotenv`、`pandas`、`yfinance`(`openpyxl` はExcelを読むときだけ)。
3. `python grid_backtest.py` を実行する。
4. 完了後、`grid_result.csv` と画面表示を確認する。
   - まず threshold=0(全決算を買う)と、閾値ごとの超過リターンを比べる。LLMスコアに付加価値があるかを判断する。
   - トレード数の少ない組合せ(例: 1銘柄1戦で勝率100%)は偶然の可能性が高い。MIN_TRADES 以上のものだけを見る。
